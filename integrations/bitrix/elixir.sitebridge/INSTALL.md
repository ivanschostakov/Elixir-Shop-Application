# Elixir Site Bridge

Комплект содержит PHP-файлы, которые устанавливаются в `/local` работающего сайта Bitrix. Ядро `/bitrix/modules` не изменяется.

## Production-состав

### Профиль сайта

- `local/api/app_integration.php` — защищённая проверка учётной записи покупателя и получение профиля/скидок;
- `local/api/app_integration.config.php` — по умолчанию выключен.

Административные аккаунты приложения с этим endpoint не связываются.

### Giveaway-бот

- `local/api/giveaways.php` — поиск пользователя и подходящих отзывов для существующего бота;
- `local/api/giveaways.config.php` — по умолчанию выключен.

Промокоды в комплект не входят: их обслуживает отдельный модуль `elixir.promo`.
Каталог содержит исходники AI для истории проекта, но они исключены из
production manifest и на сайт не загружаются.

## Копирование

Сначала сравнить целевые файлы и сохранить временную копию существующих
production-конфигов. Затем скопировать только четыре файла
`app_integration.php`, `app_integration.config.php`, `giveaways.php`,
`giveaways.config.php` в `<DOCUMENT_ROOT>/local/api`.

Нельзя заменять настроенные production-конфиги пустыми файлами из архива. PHP-код обновляется отдельно, значения конфигурации переносятся вручную.

Рекомендуемые права:

```text
каталоги: 750
PHP/JS/CSS: 640
конфиги с секретами: 600 или 640, без права записи у PHP
```

Владелец и группа выбираются по реальным пользователям deploy и PHP-FPM.

## Настройка профиля

`local/api/app_integration.config.php`:

- `enabled=true`;
- отдельный token длиной не менее 32 символов;
- точный IP backend;
- закрытый `rate_limit_dir` вне `public_html`;
- подтверждённый allowlist полей `UF_*`.

## Настройка giveaway

`local/api/giveaways.config.php`:

- `enabled=true`;
- отдельный token существующего бота.
- точный IP giveaway-сервера;
- закрытый `rate_limit_dir` вне `public_html`.

Старый fallback через `GIVEAWAY_BOT_TOKEN` в production-комплекте удалён.

## Обязательные проверки

1. Выполнить `php -l` для всех PHP-файлов.
2. Убедиться, что выключенные endpoint возвращают `503`.
3. Убедиться, что включённые endpoint без token возвращают `401`.
4. Проверить IP allowlist.
5. Проверить вход временного покупателя сайта через backend приложения.
6. Проверить обе команды giveaway-бота.
7. После проверки удалить временного покупателя и очистить кеш Bitrix/OPcache.

## Откат

- выключить endpoint в конфигурации;
- вернуть сохранённые версии PHP-файлов;
- очистить кеш Bitrix;
- временные резервные копии удалить только после подтверждения стабильной работы.
