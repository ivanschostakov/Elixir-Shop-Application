# Elixir Delivery

Модуль предоставляет закрытый серверный endpoint расчёта доставки приложения:

```text
/bitrix/tools/elixir.delivery/quote.php
```

Расчёт выполняет штатный `Bitrix Sale` через активный профиль установленного
`IPOL.СДЭК`. Поэтому тарифы, город отправления, резервные габариты/вес,
страхование, наценки, ограничения и активность способов доставки берутся из
текущих настроек сайта.

Приложение передаёт только адрес и выбранный способ. Backend приложения сам
читает корзину из PostgreSQL, сопоставляет её с Bitrix по `XML_ID` МойСклад и
подписывает server-to-server запрос. Цена из мобильного клиента не принимается
как источник истины.

## Защита

- отдельный HMAC-SHA256 secret длиной не менее 32 символов;
- timestamp с допустимым отклонением 5 минут;
- allowlist IP production backend;
- файловый rate limit в закрытом каталоге вне `public_html`;
- только `POST`, JSON и ограниченный размер тела;
- заказ Bitrix для расчёта создаётся только в памяти и никогда не сохраняется.

## Настройка

После установки откройте настройки модуля и задайте:

- `shared secret`;
- IP production backend;
- ID сайта и тип покупателя;
- коды профилей `sdek:pickup` и `sdek:courier`;
- закрытый runtime-каталог.

В production на момент интеграции активен профиль `sdek:pickup`; курьерский
профиль отключён. Поэтому приложение не должно предлагать курьерский расчёт,
пока его не включат в Bitrix.
