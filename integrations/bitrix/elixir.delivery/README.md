# Elixir Delivery

Модуль предоставляет закрытый серверный endpoint расчёта доставки приложения:

```text
/bitrix/tools/elixir.delivery/quote.php
```

Расчёт выполняет штатный `Bitrix Sale` через активный профиль установленного
`IPOL.СДЭК`. Поэтому тарифы, город отправления, резервные габариты/вес,
страхование, наценки, ограничения и активность способов доставки берутся из
текущих настроек сайта.

Приложение передаёт только адрес и выбранный способ. Backend приложения сам
читает корзину из PostgreSQL, сопоставляет её с Bitrix по `XML_ID` МойСклад и
подписывает server-to-server запрос. Цена из мобильного клиента не принимается
как источник истины.

## Определение города без догадок

- Для доставки в ПВЗ backend получает точный код выбранного пункта CDEK и
  использует `city_code` из карточки этого пункта.
- Для курьерской доставки город ищется одновременно по городу, стране и
  почтовому индексу. Результат дополнительно сверяется с координатами адреса.
- Если город не найден или результат неоднозначен, расчёт отклоняется с
  понятной ошибкой. Первый город из ответа CDEK никогда не используется как
  запасной вариант.
- Полученный код города сопоставляется с `LOCATION` Bitrix через таблицу
  установленного IPOL.СДЭК. Стоимость и срок затем считает штатный
  `Bitrix Sale`, как в checkout сайта.

Контрольный production-тест для одного товара:

| Местоположение | Checkout сайта | API приложения |
| --- | --- | --- |
| Москва | 345,26 ₽ · 2–3 дня | 345,26 ₽ · 2–3 дня |
| Уфа | 185,14 ₽ · 1–2 дня | 185,14 ₽ · 1–2 дня |

## Защита

- отдельный HMAC-SHA256 secret длиной не менее 32 символов;
- timestamp с допустимым отклонением 5 минут;
- allowlist IP production backend;
- файловый rate limit в закрытом каталоге вне `public_html`;
- только `POST`, JSON и ограниченный размер тела;
- заказ Bitrix для расчёта создаётся только в памяти и никогда не сохраняется.

## Настройка

После установки откройте настройки модуля и задайте:

- `shared secret`;
- IP production backend;
- ID сайта и тип покупателя;
- коды профилей `sdek:pickup` и `sdek:courier`;
- закрытый runtime-каталог.

В production на момент интеграции активен профиль `sdek:pickup`; курьерский
профиль отключён. Поэтому приложение не должно предлагать курьерский расчёт,
пока его не включат в Bitrix.

## Товары только для приложения

Если тестовый товар должен оставаться выключенным и невидимым в публичном
каталоге сайта, его UUID МойСклад можно добавить в настройку
`UUID товаров только для приложения`. Для таких UUID закрытый endpoint создаёт
только временную позицию расчёта по цене и весу из каталога Bitrix, не активируя
родительскую карточку и не сохраняя заказ. Остальные скрытые товары по-прежнему
отклоняются штатным провайдером Bitrix.
