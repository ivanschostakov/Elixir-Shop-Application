# Elixir Catalog Sync

Модуль делает публичный каталог Bitrix (production: инфоблок `2`) источником
контента карточек приложения:

- `DETAIL_TEXT`, затем `PREVIEW_TEXT` → `products.description`;
- `SPOSOB_PRIMENENIYA` → `products.usage`;
- `SROK_KHRANENIYA_1` → `products.expiration` (в приложении это вкладка «Хранение»).

Поля `ELIXIR_APP_DESCRIPTION`, `ELIXIR_APP_USAGE` и `ELIXIR_APP_STORAGE`
остаются необязательными точечными переопределениями: непустое значение имеет
приоритет над публичным полем, пустое — не скрывает публичный контент.
Если публичное поле также пусто, модуль читает ранее заполненное app-only поле
из технического инфоблока `21`. Благодаря этому переключение источника не
удаляет существующий контент приложения.

Активные элементы публичного каталога имеют безусловный приоритет. Неактивный
элемент допускается только как уникальный резервный источник по валидному UUID,
если в активной части каталога нет элемента с тем же UUID или артикулом.
Неактивные дубли без валидного UUID и архивные конкуренты активных карточек в
выгрузку не попадают.

Сначала используется точное совпадение `XML_ID` Bitrix и `system_id`
приложения. Для товаров, которые МойСклад пересоздал с новым UUID,
разрешён резервный поиск только по уникальному артикулу `CML2_ARTICLE`.
Дубли артикулов автоматически отклоняются; сопоставления по названию нет.
Название, цена, остаток, активность и варианты модулем не изменяются.

Подтверждённый UUID приложения сохраняется в служебном свойстве
`ELIXIR_APP_SYSTEM_ID`. Это делает последующие циклы независимыми от старого
`XML_ID` Bitrix и не влияет на публичную карточку товара.

Модуль только читает публичные поля. `PREVIEW_TEXT`, `DETAIL_TEXT`, свойства,
публичный шаблон и поведение сайта не меняются.

Endpoint:

```text
/bitrix/tools/elixir.catalogsync/sync.php
```

Он принимает только подписанный `POST {"action":"pull"}` с production-IP
приложения. Используются HMAC-SHA256, timestamp ±5 минут, IP allowlist,
файловый rate limit вне `public_html` и отдельный secret.

Если и app-only переопределение, и публичное поле пусты, соответствующее поле
приложения очищается.

## Где редактировать

1. В административной панели Bitrix открыть фактический публичный каталог
   (инфоблок `2`) и нужный товар.
2. Редактировать стандартное подробное описание, «Способ применения» или
   «Срок хранения».
3. Сохранить товар. Изменение появится в приложении не позднее чем через
   пять минут.

После запуска модуля эти поля редактируются только в Bitrix. Изменение
одноимённых полей в админке приложения будет заменено значением публичной
карточки Bitrix на следующем цикле.

Удаление модуля не удаляет свойства или записанный в них контент.
