# Каталог iOS: один серверный переключатель

Используется то же приложение, bundle ID и канал обновлений. Отдельного приложения,
локального флага или проверки аккаунта Apple нет. Политика одинаковая для всех iOS-пользователей.

В `backend/.env`:

```dotenv
APPLE_DEV_MODE=true
```

- `true` — недоступны каталог, категории, поиск товаров, баннеры, рекомендации,
  избранное, скидки, черновики, корзина и оформление новых заказов на iOS.
- `false` — эти функции доступны.
- Android, веб и админка не ограничиваются этим флагом.
- По умолчанию значение `true`. Флаг читается при старте процесса.

AI-чат, общий чат, поддержка, профиль и история существующих заказов остаются.
В AI-чате отключаются коммерческие инструменты, карточки товаров и добавление в
корзину, а запрос к модели запрещает коммерческие рекомендации. Это не модератор
произвольных сообщений общего чата и не гарантия соблюдения всех требований App Store.
Изменение доступности функций должно быть прозрачно указано Apple; флаг не предназначен
для показа проверяющим поведения, отличающегося от поведения для пользователей.

Сервер запрещает iOS-запросы к каталогу и новым заказам, а не только скрывает кнопки.
Для определения платформы приложение посылает `X-App-Platform`. Это механизм
доступности официального клиента, не замена авторизации или аттестации устройства.
Старые клиенты без заголовка распознаются только при наличии iPhone/iPad в User-Agent.

Рекламные push фильтруются по платформе каждого устройства. Уведомления о статусах
существующих заказов и ответы поддержки сохраняются. Удаление токенов не требуется.

## Развёртывание

1. Доставить изменения backend и frontend. Миграций БД и изменений Bitrix нет.
2. Указать `APPLE_DEV_MODE=true` в `backend/.env` на сервере приложения.
3. Пересоздать API и процессы, отправляющие push, чтобы они перечитали окружение.
   Имена сервисов сверить через `docker compose config --services`; как минимум API,
   notifications, admin jobs/automation и Telegram polling, если они запущены.
4. Один раз доставить этот JS-клиент через OTA. Приложение, которое ещё не получило
   обновление, не умеет скрывать интерфейс по новому флагу.
5. Проверить `GET /api/v1/app-version`: ответ содержит `apple_dev_mode: true`.
   Запрос `GET /api/v1/products` с `X-App-Platform: ios` должен вернуть `403` с кодом
   `ios_catalog_unavailable`; с `X-App-Platform: android` каталог должен работать.

Приложение обновляет политику при запуске, возвращении из фона и каждую минуту,
пока оно активно. Если политика не загрузилась, на iOS каталог остаётся закрытым;
остальные разделы доступны. После первого OTA последующие переключения требуют
только изменения серверной переменной и перезапуска серверных процессов, не нового OTA.

## Исправление карты в этом обновлении

- Убран запуск через `InteractionManager`, способный ждать бесконечную анимацию.
- Таймаут 20 секунд охватывает заголовки и тело HTTP-ответа, включая случай,
  когда нативный fetch не реагирует на abort.
- Пункты выдачи загружаются независимо от тайлов карты; ответы провайдеров
  показываются по мере готовности.
- В нативную карту передаются до 1 500 ближайших точек текущей области вместо
  массива до 80 000 точек. Набор обновляется после перемещения/масштабирования;
  данные остальных точек не удаляются, поиск остаётся доступным.
- Истечение 15 секунд не считается успешной загрузкой карты: показывается кнопка
  повтора. Загрузка точек больше не перекрывает карту полноэкранным размытием.
- Нативный код, ключ MapKit и конфигурация iOS-сборки не менялись; эти исправления
  совместимы с OTA текущего runtime. Отображение тайлов нужно дополнительно
  проверить на реальном устройстве с обновлением.

Проверки: `npm run typecheck`, `npm run test:regressions` в frontend;
`pytest tests/test_platform_availability.py tests/test_app_version_api.py
tests/test_push_notifications.py tests/test_ai_chat_api.py` в backend.

Локальная проверка 02.09.2026: 79 серверных и 9 клиентских тестов прошли,
TypeScript и ESLint без ошибок (в карте остаются прежние предупреждения зависимостей
React hooks), iOS JS-пакет успешно экспортирован. Read-only запрос к продакшену
вернул 9 841 CDEK-точку с валидными координатами, Яндекс — пустой массив.
На реальных CDEK-данных выбор области Москвы дал 478 точек за ~1 мс на рабочем
компьютере; это не замер производительности iPhone. Нативная карта на телефоне
в этой проверке не запускалась. Деплой и публикация OTA этими проверками не выполнялись.
